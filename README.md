# Telegram Web Proxy — установщик и менеджер

Bash-скрипт для установки, обновления, настройки и удаления Telegram Web Proxy на сервере Ubuntu/Debian x86_64.

Скрипт разворачивает **tproxy-server + MTProxy** и выбранный веб-сервер — Caddy или Nginx, настраивает systemd-службы и локальные правила firewall, получает TLS-сертификат и формирует ссылку подключения вместе с QR-кодом.

> Скрипт рассчитан на чистый или специально подготовленный сервер. Перед установкой убедитесь, что у вас есть доступ к серверу с правами root и домен, направленный на его публичный IP.

## Возможности

- **Установка и обновление** tproxy-server и MTProxy.
- **Интерактивное меню** и запуск отдельных операций из командной строки.
- **Сохранение настроек при обновлении**: скрипт считывает текущие параметры, показывает их как значения по умолчанию и оставляет их без изменений при нажатии Enter.
- **Генерация или задание секрета MTProxy** в форматах `plain` и `dd`.
- **Автоматическая генерация base path** для Web Proxy либо использование собственного пути.
- **Выбор веб-сервера Caddy или Nginx**. Caddy управляет TLS самостоятельно; Nginx использует Certbot и Let's Encrypt с автоматическим продлением сертификата.
- **Создание сайта-заглушки** с несколькими страницами, CSS и favicon.
- **Настройка systemd-служб** для tproxy-server, MTProxy, firewall и периодического обновления конфигурации MTProxy.
- **Локальная фильтрация backend-портов** MTProxy с помощью nftables.
- **Проверка конфигурации и готовности сервисов** после установки/обновления.
- **Формирование ссылки подключения** Telegram Web Proxy.
- **Генерация QR-кода**: отображение в терминале и сохранение PNG-файла.
- **Просмотр текущей конфигурации**, состояния служб и слушающих TCP-портов.
- **Удаление приложения** с возможностью оставить Caddy или удалить также установленные скриптом пакеты.

## Архитектура и порты

Внешний трафик проходит через выбранный веб-сервер. Caddy самостоятельно получает и продлевает TLS-сертификаты; Nginx использует Certbot/Let's Encrypt. Оба варианта обслуживают HTTPS и проксируют Web Proxy на локальный tproxy-server, который взаимодействует с MTProxy.

| Порт | Назначение | Доступ |
|---|---|---|
| TCP 80 | HTTP, перенаправление на HTTPS и ACME/Let's Encrypt | Открыть извне |
| TCP 443 | HTTPS, сайт и Web Proxy | Открыть извне |
| TCP 8080 | Relay tproxy-server по умолчанию | Только localhost |
| TCP 8081 | Admin/health tproxy-server по умолчанию | Только localhost |
| TCP 2398 | Backend MTProxy | Внутренний |
| TCP 8888 | Служебный порт MTProxy | Внутренний |

Relay и admin-порт привязаны к `127.0.0.1`. Порты 2398 и 8888 блокируются локальными правилами nftables на внешних интерфейсах. **Не открывайте их в firewall провайдера или сервера.** Для описанной конфигурации входящий UDP не требуется.

Если вы используете нестандартные relay/admin-порты, они также остаются локальными — открывать их в интернет не нужно.

## Требования

- Ubuntu или Debian (другие дистрибутивы скрипт не проверяет).
- Архитектура **x86_64**.
- Доступ root или запуск через `sudo`.
- Доменное имя с настроенной **A-записью**, указывающей на публичный IPv4-адрес сервера. DNS-проверка выполняется через resolver 1.1.1.1.
- Свободные входящие TCP-порты **80 и 443**. Порт 443 должен быть доступен выбранному веб-серверу (Caddy или Nginx).
- Доступ сервера в интернет для установки пакетов и загрузки исходников/бинарных файлов.
- Возможность управлять systemd и nftables.

Во время установки скрипт автоматически устанавливает необходимые системные зависимости, в том числе `qrencode` для создания QR-кодов, `jq`, `git`, `curl`, `openssl`, `nftables`, `dnsutils`, `netcat-openbsd` и инструменты сборки. Если подходящей версии Go нет, скрипт устанавливает закреплённую версию Go. Caddy устанавливается в закреплённой версии с проверкой контрольной суммы; Nginx и Certbot устанавливаются из репозитория пакетов ОС.

## Быстрый старт

### 1. Подготовьте DNS и firewall

Создайте A-запись домена, например:

```text
proxy.example.com → ПУБЛИЧНЫЙ_IP_СЕРВЕРА
```

Разрешите входящие TCP 80 и 443 в firewall операционной системы и в панели управления VPS/облачного провайдера. Убедитесь, что эти порты не заняты другими сервисами.

### 2. Скачайте скрипт

```bash
curl -fsSL https://raw.githubusercontent.com/RSaenko/tgproxy/main/tgweb-install.sh -o tgweb-install.sh
chmod +x tgweb-install.sh
```

### 3. Запустите меню

```bash
sudo ./tgweb-install.sh
```

Выберите пункт **1 — Установить tproxy-server** и следуйте подсказкам. Скрипт предложит выбрать Caddy или Nginx, затем запросит домен, email для Let's Encrypt, порты и формат секрета. Пункт **6 — Инструменты** открывает подменю: единая диагностика служб, портов, конфигураций и ошибок, создание и восстановление резервной копии.

Для секрета можно выбрать автоматическую генерацию или ввести собственное значение. Поддерживаются 32 строчные шестнадцатеричные символа, а также такой же секрет с префиксом `dd`.

После подтверждения скрипт установит зависимости, соберёт компоненты, запишет конфигурацию, настроит службы, проверит их состояние и выведет ссылку подключения и QR-код.

## Использование из командной строки

Общий формат:

```bash
sudo ./tgweb-install.sh <команда> [параметры]
```

### Установка

Интерактивная установка:

```bash
sudo ./tgweb-install.sh install
```

Установка с параметрами:

```bash
sudo ./tgweb-install.sh install \
  --hostname proxy.example.com \
  --email admin@example.com \
  --port 8080 \
  --admin-port 8081
```

Если не указать `--secret`, скрипт предложит сгенерировать секрет в интерактивном режиме. Для полностью автоматической установки используйте `--non-interactive` (или `-y`) и передайте обязательные параметры:

```bash
sudo ./tgweb-install.sh install \
  --hostname proxy.example.com \
  --email admin@example.com \
  --port 8080 \
  --admin-port 8081 \
  --non-interactive
```

В non-interactive режиме секрет будет сгенерирован автоматически, если не передан через `--secret`.

### Обновление

```bash
sudo ./tgweb-install.sh update
```

При интерактивном обновлении скрипт загружает действующие настройки. Текущие значения отображаются в квадратных скобках; нажатие Enter сохраняет их. Можно изменить домен, email, base path, relay/admin-порты, секрет, количество workers и максимальное число соединений.

По умолчанию текущий секрет сохраняется. Чтобы заменить его, введите `n` в запросе о замене секрета; новый секрет можно ввести вручную или сгенерировать.

Для обновления без вопросов:

```bash
sudo ./tgweb-install.sh update --non-interactive
```

Можно передать отдельные параметры, которые требуется изменить. Остальные настройки будут взяты из текущей конфигурации. Обновление запускается с пропуском `go test`.

### Просмотр конфигурации

```bash
sudo ./tgweb-install.sh config
```

Команда выводит домен, base path, локальные адреса relay/admin, backend MTProxy, параметры workers/connections, email Let's Encrypt и выбранный веб-сервер. Также отображаются секрет и его формат. Если конфигурационные файлы доступны, команда формирует ссылку подключения и QR-код; путь к PNG указывается в конце отчёта.

Сохранить текстовый отчёт в файл:

```bash
sudo ./tgweb-install.sh config --output /root/tproxy-config.txt
```

Файл отчёта создаётся с правами `0600`. QR-код при этом также генерируется и выводится в терминал.

### Удаление

Удалить tproxy-server и связанные с ним компоненты, оставив выбранный веб-сервер:

```bash
sudo ./tgweb-install.sh uninstall --keep-web-server
```

Без `--keep-web-server` скрипт отдельно спросит, нужно ли удалить Caddy и/или Nginx.

Полное удаление приложения и установленных скриптом пакетов:

```bash
sudo ./tgweb-install.sh purge
```

Команда `purge` дополнительно предложит удалить системные пакеты из своего списка и выполнить `apt autoremove`. Внимательно проверьте список: некоторые пакеты могут использоваться другими приложениями на сервере.

Флаг `--yes` подтверждает запросы автоматически. Используйте его только если заранее понимаете последствия:

```bash
sudo ./tgweb-install.sh uninstall --keep-web-server --yes
```

## Параметры установки и обновления

| Параметр | Описание |
|---|---|
| `--hostname FQDN` | Домен Web Proxy в нижнем регистре, например `proxy.example.com` |
| `--web-server caddy\|nginx` | Веб-сервер; по умолчанию Caddy. Для Nginx TLS-сертификат выпускает и обновляет Certbot |
| `--email EMAIL` | Email для Let's Encrypt |
| `--secret SECRET` | Секрет: 32 lowercase hex-символа или `dd` + 32 hex-символа |
| `--secret-prefix plain\|dd` | Формат генерируемого секрета |
| `--base-path SLUG\|none` | Собственный путь Web Proxy или `none` для корневого пути; при установке без параметра путь генерируется автоматически |
| `--site-dir PATH` | Каталог сайта; значение по умолчанию — `/srv/tproxy-site` |
| `--no-site` | Не создавать сайт-заглушку |
| `--workers N` | Количество MTProxy workers, от 1 до 256; по умолчанию 1 |
| `--max-connections N` | Максимальное число соединений MTProxy; по умолчанию 4096 |
| `--port N` | Локальный relay-порт; по умолчанию 8080 |
| `--admin-port N` | Локальный admin-порт; по умолчанию 8081 |
| `--skip-tests` | Пропустить `go test ./...` |
| `--non-interactive`, `-y` | Не задавать интерактивные вопросы при установке/обновлении |

Порты relay и admin должны различаться и находиться в диапазоне 1024–65535. При интерактивной установке скрипт проверяет занятость выбранных портов.

Пример установки с собственным секретом и путём:

```bash
sudo ./tgweb-install.sh install \
  --hostname proxy.example.com \
  --email admin@example.com \
  --secret 0123456789abcdef0123456789abcdef \
  --base-path my-proxy \
  --port 8080 \
  --admin-port 8081
```

## Ссылка подключения и QR-код

По завершении установки или обновления скрипт выводит Telegram-ссылку подключения и QR-код в терминале. Команда `config` делает то же самое на основании действующей конфигурации.

PNG-файл сохраняется по адресу:

```text
/etc/tproxy-server/proxy-qr.png
```

Права на файл — `0600`, владелец — root. Чтобы забрать файл на локальный компьютер, например, сначала скопируйте его в доступное для чтения место или используйте передачу через root-доступ. Не публикуйте QR-код и ссылку: они содержат секрет подключения.

Проверить файл на сервере:

```bash
sudo file /etc/tproxy-server/proxy-qr.png
sudo ls -l /etc/tproxy-server/proxy-qr.png
```

## Проверка после установки

Скрипт сам выполняет проверки конфигурации и ждёт готовности relay. Дополнительно состояние можно проверить вручную:

```bash
sudo systemctl status tproxy-server
sudo systemctl status mtproxy
sudo systemctl status tproxy-firewall
sudo systemctl status caddy
# или, если выбран Nginx:
sudo systemctl status nginx
```

Проверка health/ready endpoints (admin-порт по умолчанию 8081):

```bash
curl -fsS http://127.0.0.1:8081/healthz
curl -fsS http://127.0.0.1:8081/readyz
curl -fsS https://proxy.example.com/
```

Для просмотра журналов:

```bash
sudo journalctl -u tproxy-server -n 100 --no-pager
sudo journalctl -u mtproxy -n 100 --no-pager
sudo journalctl -u caddy -n 100 --no-pager
# или, если выбран Nginx:
sudo journalctl -u nginx -n 100 --no-pager
```

## Что устанавливается и где хранится

| Путь | Назначение |
|---|---|
| `/usr/local/bin/tproxy-server` | Бинарный файл tproxy-server |
| `/usr/local/bin/mtproxy` | Бинарный файл MTProxy |
| `/usr/local/bin/caddy` | Caddy |
| `/opt/tproxy-server` | Закреплённая версия исходного репозитория tproxy-server и deploy-файлы |
| `/etc/tproxy-server/config.json` | Конфигурация tproxy-server |
| `/etc/tproxy-server/profiles.json` | Профиль и секрет подключения |
| `/etc/tproxy-server/proxy-qr.png` | QR-код подключения |
| `/etc/tproxy-server/acme-email` | Email для Let's Encrypt, сохраняется независимо от выбранного веб-сервера |
| `/etc/tproxy-server/web-server` | Маркер выбранного веб-сервера (`caddy` или `nginx`) |
| `/etc/tproxy-server/firewall.nft` | Правила firewall backend |
| `/etc/mtproxy/mtproxy.env` | Параметры MTProxy |
| `/etc/caddy/Caddyfile` | Конфигурация Caddy |
| `/etc/nginx/sites-available/tproxy-server` | Конфигурация Nginx (если выбран) |
| `/etc/nginx/conf.d/tproxy-websocket-map.conf` | Map для WebSocket-соединений Nginx |
| `/etc/letsencrypt/` | Сертификаты и настройки Certbot (если выбран Nginx) |
| `/etc/letsencrypt/renewal-hooks/deploy/reload-tproxy-nginx` | Перезагрузка Nginx после продления сертификата |
| `/srv/tproxy-site` | Сайт-заглушка по умолчанию |
| `/usr/local/sbin/refresh-mtproxy-config` | Скрипт обновления конфигурации MTProxy |

Также создаются systemd units и служебные пользователи для компонентов, которым они необходимы. Caddy и Nginx устанавливаются как альтернативные веб-серверы; одновременно для Web Proxy используется только один из них.

## Важные замечания по безопасности

- Не передавайте третьим лицам секрет MTProxy, ссылку подключения или QR-код.
- Файлы `profiles.json`, `mtproxy.env` и QR-код содержат секретные данные или производные от них; не меняйте их права доступа на публичное чтение.
- Не открывайте в интернет relay/admin-порты и внутренние порты MTProxy.
- Не запускайте `purge` без проверки списка удаляемых пакетов.
- При обновлении скрипт синхронизирует исходники upstream на закреплённый commit в `/opt/tproxy-server`. Не храните собственные изменения в этом каталоге: они могут быть затёрты.
- Скрипт рассчитан на указанную архитектуру и systemd-системы. Перед использованием на рабочем сервере рекомендуется сделать резервную копию конфигурации.

## Используемые компоненты

- [telegramdesktop/tproxy-server](https://github.com/telegramdesktop/tproxy-server) — relay и Web Proxy.
- [Caddy](https://caddyserver.com/) — HTTPS, TLS и reverse proxy.
- [Nginx](https://nginx.org/) — альтернативный веб-сервер и reverse proxy.
- [Certbot](https://certbot.eff.org/) — выпуск и автоматическое продление TLS-сертификатов для Nginx.
- [MTProxy](https://github.com/TelegramMessenger/MTProxy) — backend прокси.
- [qrencode](https://github.com/fukuchi/libqrencode) — генерация QR-кодов.


## Обслуживание и восстановление

Скрипт поддерживает команды:

```bash
sudo ./tgweb-install.sh diagnostics
sudo ./tgweb-install.sh backup
sudo ./tgweb-install.sh backup /root/tproxy-backup.tar.gz
sudo ./tgweb-install.sh restore /root/tproxy-backup.tar.gz
```

- `diagnostics` запускает диагностику: состояние systemd-служб с указанием их unit-имён, проверку JSON-конфигураций, список слушающих TCP-портов и последние ошибки из журналов systemd.
- `backup` архивирует конфигурации tproxy-server, MTProxy, выбранного веб-сервера (Caddy или Nginx), сертификаты Let's Encrypt и связанные systemd units. В архив входят email Let's Encrypt и маркер выбранного веб-сервера. Архив создаётся с правами `0600`.
- `restore` восстанавливает файлы из архива и выполняет `systemctl daemon-reload`. После восстановления проверь конфигурацию и состояние служб вручную.

**Важно:** backup/restore сохраняет конфигурационные файлы, но не является автоматическим rollback обновления. Он не возвращает предыдущие бинарники, исходники upstream, пакеты или состояние firewall. Перед обновлением отдельно сохрани важные данные и проверь восстановление на тестовой машине.

Существующий каталог сайта при повторной установке не должен автоматически переписываться или менять права. При удалении прокси каталог сайта сохраняется; удаляй его вручную после проверки содержимого, если он больше не нужен. Секреты и ссылки подключения выводятся в отчёте установки и команды `config`; QR-код также отображается в терминале и сохраняется в PNG. Не оставляй вывод в общедоступных логах и не передавай его третьим лицам.
